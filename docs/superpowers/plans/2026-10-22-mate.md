# Mate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A free, open-source, native macOS notch app ("Mate") with feature parity to Agent Limit that shows session/weekly limits for Claude, Codex, Cursor, Gemini CLI, Copilot and Grok, supports several accounts per provider, can switch the active Claude Code account, and idles at 0 % CPU.

**Architecture:** A Swift package with two targets, the same shape as Rambla (`~/Desktop/Proyectos/scroll`). `MateCore` is a pure, unit-tested library: model, pace, alerts, account ownership, response/credential/log parsers, aggregates, scheduling and notch geometry. `Mate` is an AppKit `LSUIElement` app: keychain, FSEvents, networking, one provider object per provider, a main-actor `UsageStore` that owns all state, the notch panel (AppKit window + SwiftUI content), the usage window (Swift Charts), settings and onboarding. All I/O lives in `Mate`; every decision lives in `MateCore`.

**Tech Stack:** Swift 6.3 toolchain (language mode 5), SwiftPM, Command Line Tools only (no Xcode), Swift Testing, AppKit, SwiftUI, Swift Charts, Security.framework, CoreServices (FSEvents), Network.framework (OAuth loopback), libsqlite3 (Cursor), ServiceManagement. No third-party dependencies.

**Spec:** `docs/superpowers/specs/2026-10-22-mate-design.md` (Spanish). Executors read both documents. Rambla's code is the reference for anything this plan says to "port".

## Global Constraints

- Platform: macOS 14.0+ (`LSMinimumSystemVersion` 14.0), arm64 only. Build with `swift build -c release`; never require Xcode or `xcodebuild`.
- No third-party packages. Only Apple frameworks and the system `libsqlite3`.
- `Package.swift`: `swift-tools-version: 6.0`, `swiftLanguageModes: [.v5]`, the same Command-Line-Tools Swift Testing flags as Rambla's `Package.swift`.
- Bundle id `io.github.coru29.Mate`, app name `Mate`, `LSUIElement` = true, no Dock icon, no menu bar status item.
- Signing: identity `Rambla Local Signing` from keychain `${MATE_SIGNING_KEYCHAIN:-$HOME/Desktop/Proyectos/scroll/.signing/rambla-signing.keychain-db}`, password from `RAMBLA_SIGNING_PASSWORD` or `security find-generic-password -s io.github.coru29.Rambla.signing -w`. `sign.sh` never creates an identity; if the keychain or password is missing it exits 1 with a clear message. Never print, log or commit the password.
- UI copy: Spanish is the source language (the localization keys, Rioplatense neutral, voseo: "Cerrá", "Tocá"); English in `Packaging/en.lproj`. Identifiers and code comments are English.
- Tokens are sent only to their own provider's host (table in the spec, "Proveedores"). The only other network host is `api.github.com` for updates. `URLSession` uses `.ephemeral` configuration.
- An account whose `owner == .agent` is never refreshed and never written by Mate, except by the explicit "Usar en Claude Code" switch (Task 12).
- Zero CPU when idle: no repeating timers or polling. Allowed: one-shot timers (activity expiry, resets, next fetch), FSEvents, `NSWorkspace` notifications, `NSBackgroundActivityScheduler` for idle fetches and the daily update check, and animation while the panel or an alert animates. Every timer sets `tolerance` ≥ 10 % of its interval.
- Mate's own keychain items: service `io.github.coru29.Mate.<provider>`, account = Mate account id. Preferences in `UserDefaults` suite `io.github.coru29.Mate`. Data in `~/Library/Application Support/Mate/`.
- Git: `git init` in Task 1 with Rambla's Conventional Commits `commit-msg` hook. Every commit message ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never push or create a GitHub repo without asking the user (Task 15).
- Build agents must not read credential files or keychain items themselves (the auto-mode classifier blocks it and it is the user's data). Live checks run the built app, which reads them under macOS's own keychain prompt, and print only non-secret fields (email, percents, dates).

## Review Focus

1. **Mate refreshes or rewrites the token of the account an agent is using** (logs the user out): any refresh path must check ownership first. Tests: Task 4 `agentOwnedAccountIsNeverRefreshable`; Task 8 `providerRefusesRefreshForAgentOwned`.
2. **The user `/login`s back into an account Mate already owns, or the same identity shows up in two config dirs**: exactly one owner per account, no duplicate accounts. Tests: Task 4 `reloginTransfersOwnershipToAgent`, `sameIdentityInTwoConfigDirsIsOneAccount`.
3. **Network offline, 401, 429 or a changed JSON shape**: keep the last snapshot, mark it stale, back off, never crash or show 0 %. Tests: Task 5 `malformedResponsesThrowNotCrash`; Task 7 `backoffDoublesAfterFailureUpToCap`; Task 9 live check with Wi-Fi off.
4. **External display only (lid closed), display unplugged or resolution change**: the panel moves to the right screen and draws a fake notch there. Tests: Task 7 `screenWithoutNotchGetsFakeNotch`, `pickBuiltInWhenPresent`; Task 9 live check with the external monitor.
5. **Huge or rewritten log files** (first launch over months of logs, a file truncated or replaced, a half-written last line, the same Claude message logged twice): incremental, correct, deduplicated. Tests: Task 6 `partialLastLineIsKeptForNextRead`, `truncatedFileRestartsFromZero`, `duplicateClaudeMessageCountedOnce`.

- [ ] **Step 2:** Run `scripts/test.sh --filter Pace` → FAIL (undefined).

### Task 7: Activity, fetch schedule and notch geometry (MateCore)
